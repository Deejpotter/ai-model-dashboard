Make the choice, not the spreadsheet.

A UX audit and redesign proposal for turning a useful model catalogue into a reliable decision tool.

01 / Decision

Approve a decision-first redesign, not a cosmetic table refresh.

The current product has the right data and useful capabilities. Its primary interface still requires the user to interpret a dense 12-column table before answering the questions the product exists to answer: which model should I use, why, and what will it cost?

Recommendation

Replace the table-first default with guided discovery, compact decision cards, model detail on demand, a persistent comparison tray, and scenario-based cost planning.

This keeps the advanced data available without making it the first obstacle in every decision.

Approval checklist

  • Decision-first information architecture
  • Unknown pricing is never treated as $0
  • URL-persisted filters, scenarios, and comparisons
  • Accessibility baseline in Phase 1

03 / Diagnosis

Six changes will make the experience materially more useful.

P0

Correct the pricing truth model

The calculator turns absent input, cache, or output price into zero. The implementation confirms this behaviour. Price absence must mean Pricing unavailable, not $0 and never “cheapest.”

Required behaviourExclude incomplete pricing from lowest-cost claims; show it separately with the missing component identified.
P0

Make the catalogue a shortlist tool

The current view always renders notes, model IDs, modes, prices, and four score columns together. The catalogue markup confirms the 12-field layout. Show only decision-critical information initially; make the rest available in a detail drawer.

P0

Start with intent, not raw filters

Search, provider, and favourites are the only current catalogue filters. View the filter controls. Add coding, vision, reasoning, context, availability, provider, and price filters, with quick starts for common choices.

P1

Move comparison into the main journey

Comparison begins from a long native select menu in a separate view. View the current comparison flow. A persistent tray should allow users to add candidates as they browse, then compare two to four finalists.

P1

Expose data confidence and feedback

Loading, error, source, freshness, and post-favourite feedback are absent. The client holds filters, active view, scenario values, and comparisons only in memory. View the current state model.

P1

Repair the accessibility baseline

Form controls need labels, and keyboard-operable controls need visible focus indicators (World Wide Web Consortium, 2024; World Wide Web Consortium, 2026a). The tab-like controls should either follow the expected tab pattern or become regular view navigation (World Wide Web Consortium, 2026b).

04 / Direction

One product, four decision surfaces.

The redesign keeps every useful capability but orders it around the user’s actual choices. Raw data remains available, but it no longer dominates the first screen.

01

Discover Models

Quick starts and filters form a shortlist by task, capability, cost, context, provider, and availability.

02

Model Detail

An on-demand drawer holds price breakdown, evidence, source, freshness, notes, and advanced metadata.

03

Compare

A global tray carries finalists between views, then opens a focused cost/capability/evidence comparison.

04

Cost Planner

Named workload scenarios show viable fully priced models, budget impact, and baseline savings.

Design principle

Every recommendation should say what it optimised for. Example: “Lowest fully priced vision option for this workload” rather than a vague “best model” badge. Missing or stale evidence must remain visible.

05 / Scope

Build the reliable core first, then the decision accelerators.

Phase 1: Decision foundation

  • Responsive catalogue cards/list and progressive filters
  • Quick starts for task, price, and availability
  • Accessible model detail drawer
  • Persistent comparison tray and comparison screen
  • Unknown-pricing, loading, error, empty, and success states
  • URL state for filters, comparison, view, and scenario inputs
  • Semantic controls, focus treatment, keyboard support, live feedback

Phase 2: Decision tools

  • Named workload scenarios, budgets, and baselines
  • Transparent rule-based ranking with visible rationale
  • Coverage, freshness, and source-confidence badges
  • Optional saved views, subject to a separate persistence decision
  • Refined comparison emphasis for meaningful deltas

Not in scope

No silent automatic recommendation for production use; no claim that a benchmark predicts all real-world performance; no provider purchasing or usage actions; no auth or multi-user collaboration; no full visual rebrand.

Deployment credential policy

If a later approved integration needs a provider key, it will run server-side and receive its secret through Coolify environment variables. Existing credentials may be sourced from the Krasus environment file, but keys will never be committed, displayed in the UI, copied into this report, or sent to the browser. Production variable changes remain deferred until the specific integration and deployment are approved.

06 / Success

The redesign is approved when users can make a defensible choice quickly.

User outcomes

  1. Find fully priced vision models under an output-price ceiling in two filter interactions or fewer.
  2. Add two models to comparison directly from discovery.
  3. Identify the cheapest fully priced viable model for a workload and inspect the calculation.
  4. Open a copied URL and recover the selected view, filters, candidates, and scenario.
  5. Tell whether a value is unavailable, stale, or traceable to a source.

Quality baseline

  1. Every form control has a visible label or correct accessible name.
  2. Every interactive control has visible keyboard focus.
  3. Sort, favourite, compare, drawer, and navigation controls are keyboard-operable.
  4. Every asynchronous state provides loading, error, and success feedback.
  5. No essential mobile action requires horizontal page scrolling.
  6. npm run lint passes before deployment.
